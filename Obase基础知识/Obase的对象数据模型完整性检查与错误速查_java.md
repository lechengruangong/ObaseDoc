完整性检查是对Obase对象数据模型的校验,分为对象类型通用检查,实体型检查和关联型检查三种.

顾名思义,实体型检查和关联型检查就是对实体型和关联型分别生效的检查,而对象类型通用检查是同时对实体型和关联生效的检查,如果完整性检查没有通过,会抛出特定类型的异常IntegrityCheckFailException.

IntegrityCheckFailException包含一个HashMap<string, List<string>>类型的错误消息字典ErrorMessageDictionary,在此字典中可以查看到当前检查失败的消息.

ErrorMessageDictionary的键是类型的全名,值是错误消息列表,类型名称包含以下三种:
1. 实体型,就是类型的全名.
2. 显式关联型,就是类型的全名.
3. 隐式关联型,是一个特殊的内部名称,分为三个部分:
    1. 第一部分固定为ImplicitAssociation表示这是一个隐式关联型.
    2. 第二部分为参与此关联各个关联端的类型名称,以下划线作为分隔符.
    3. 第三部分为<>数字组成的定义顺序.

错误消息字典中的每一条错误信息前都会带有来源前缀,前缀分为[ODM]和[SODM]两种,[ODM]表示此错误来自于对象数据模型(Object Data Model)的完整性检查,[SODM]表示此错误来自于序列化对象数据模型(Serialization Object Data Model)的完整性检查,这两个前缀定义在IntegrityCheckFailException的ODM_MESSAGE_PREFIX和SODM_MESSAGE_PREFIX常量中,关于序列化对象数据模型可以参考[Obase如何配置属性复杂序列化](../Obase进阶使用/Obase如何配置属性复杂序列化_java.md).

建造模型时会先对序列化对象数据模型进行完整性检查,如果序列化对象数据模型的配置有误,则错误消息字典中只会包含带[SODM]前缀的错误信息,此时不会再进行对象数据模型的完整性检查.

以下是目前已有的完整性检查中错误的速查表:

| 错误信息                                                   | 需要检查的配置或修改方法                                 |
|--------------------------------------------------------|----------------------------------------------|
| XXX未配置有效的构造函数.                                         | 类内没有合适的无参构造函数,需要手动后调用hasConstructor方法指定构造器.  |
| XXX未配置映射表.                                              | 检查toTable方法配置的映射表是不是空.                       |
| XXX配置为继承YYY,却没有配置具体类型判别标志.                              | 检查是否使用hasConcreteTypeSign方法配置了具体类型判别标志.      |
| XXX存在派生类型,作为基类型却没有配置具体类型判别标志.                           | 检查是否使用hasConcreteTypeSign方法配置了具体类型判别标志.      |
| XXX配置为继承YYY,但映射表与父类不一致,父类映射表为ZZZ,当前为WWW.                | 检查继承的父类配置toTable方法配置的映射表和子类是否一致.             |
| XXX及其派生类型的具体类型判别标志值存在重复,具体类型判别标志值序列为:....                | 检查使用hasConcreteTypeSign方法配置的值是否有重复.          |
| XXX的构造器参数个数与父类参数个数不一致,XXX为X个,但父类YYY的构造器参数为Y个.          | 检查子类内是否存在与父类的构造器使用的构造函数参数一致的构造函数并且是否被配置为构造器. |
| XXX的构造器第X个参数所绑定元素的类型与父类不一致,XXX为A,父类YYY为B.             | 检查子类内是否存在与父类的构造器使用的构造函数参数一致的构造函数并且是否被配置为构造器. |
| XXX的属性YYY没有设值器,且没有在构造函数中使用.                             | 检查类的属性是否有Set方法或者自己配置的设值器是否是空.                |
| XXX的属性YYY没有取值器.                                        | 检查类的属性是否有Get方法或者自己配置的取值器是否是空.                |
| 实体XXX未配置主键,请为实体指定主键属性.                                  | 检查是否设置了主键.                                   |
| 实体XXX的主键是联合主键,不能配置为自增.                                  | 检查是否为设置了多个主键的类型设置了主键自增.                      |
| 实体XXX的键属性YYY配置为自增,但类型TTT不是short,int,long之一.            | 检查是不是将不能自增的主键类型设置了主键自增.                      |
| XXX的关联引用YYY的左端和右端不能相同.                                  | 检查是不是将同一个关联引用配置了多次.                          |
| XXX的关联引用YYY是多重引用,其关联型的映射表不能与实体型自身的映射表ZZZ相同.             | 检查是不是将一对多的关联引用的映射表配置错了.                      |
| 隐式关联型XXX内只能有关联端,不应定义属性YYY.                              | 检查是不是手动指定了一个显式关联类的visible为false.             |
| 关联型XXX的关联端YYY没有映射.                                     | 检查是不是没配置关联端映射.                               |
| 关联型XXX的关联端YYY的映射键属性KKK在端类型TTT中不存在.                      | 检查关联端的映射第一个参数是不是写错了.                         |
| 关联型XXX的关联端YYY(端类型TTT)的标识属性KKK应有且仅有1个映射,实际有N个.          | 检查关联端的映射第一个参数是不是和关联端实体型主键一致.                 |

以下是序列化对象数据模型(SODM)中错误的速查表:

| 错误信息                              | 需要检查的配置或修改方法                            |
|-----------------------------------|-----------------------------------------|
| 序列化实体XXX中存在名称为空的属性.               | 检查序列化实体中是否有属性没有配置名称.                    |
| 序列化实体XXX中存在名称为空的引用.               | 检查序列化实体中是否有引用没有配置名称.                    |
| XXX的属性YYY没有取值器.                   | 检查序列化实体的属性是否有Get方法.                     |
| XXX的属性YYY没有设值器.                   | 检查序列化实体的属性是否有Set方法.                     |
| XXX的引用YYY没有取值器.                   | 检查序列化实体的引用是否有Get方法.                     |
| XXX的引用YYY没有设值器.                   | 检查序列化实体的引用是否有Set方法.                     |
| XXX没有配置构造器.                       | 检查是否使用hasConstructor方法为序列化实体配置了构造器.     |
| XXX的构造器应有X个参数,实际只配置了Y个.           | 检查是否为构造器的每一个参数都调用了hasParameter方法.      |

表中未列出的错误信息也可以根据错误信息本身的描述找到需要检查的配置,此外这些错误信息也可以使用[Obase如何验证对象数据模型](../Obase进阶使用/Obase如何验证对象数据模型_java.md)中介绍的ODM验证器直接查看,验证器会将错误信息按类型分组后输出.

在大多数情况下,完整性检查都是帮助我们进行模型校验不可或缺的一步,但如果你确定自己的配置没有任何问题但是和完整性检查相违背,可以在配置提供器createModel(ModelBuilder modelBuilder)的参数modelBuilder上调用hasIntegrityCheck(false)来关闭完整性检查.
